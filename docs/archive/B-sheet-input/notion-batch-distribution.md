> 상태: 설계 단계 (구현 전)
> 관련 문서: `docs/sheet-driven-design.md`, `docs/longform-design.md`

## 1. 기존 파일의 작동 방식

### 현재 구조

- **입력:** 유튜브 채널의 쇼츠 탭 (`/shorts`)에서 영상을 가져옵니다. `yt-dlp`로 수집합니다.
- **변환:** `ffmpeg`로 H.264 MP4로 맞춥니다.
- **출력:** 플랫폼별 업로더가 Playwright로 로그인된 Chrome 프로필을 열어 업로드합니다.
- **대상 플랫폼:** 인스타그램 릴스, 쓰레드, 틱톡, 링크드인, 페이스북, 네이버 클립

### 한 줄 요약

> **유튜브 쇼츠 → 타 SNS의 숏폼(릴스, 쇼츠 등)으로 대치**

즉, 지금 파이프라인은 **숏폼끼리만** 옮겨 주는 구조입니다. 롱폼, 이미지, 블로그는 대상이 아닙니다.

### 대치 가능한 것과 불가능한 것

| 구분 | 지금 가능 여부 |
|---|---|
| 유튜브 쇼츠 → 인스타 릴스 | 가능 |
| 유튜브 쇼츠 → 틱톡, 페이스북 릴스 등 | 가능 (플랫폼별 업로더 구현됨) |
| 유튜브 롱폼 → 어떤 플랫폼이든 | 불가 (수집 탭과 업로더가 숏폼 기준) |
| 이미지, 캐러셀 | 불가 |
| 네이버 블로그 (글 형식) | 불가 |

## 2. 시트 방식을 제안한 이유

### 현재 방식의 한계

- **입력이 유튜브에 묶여 있음:** 영상이 유튜브에 먼저 올라가 있어야 합니다.
- **형식이 하나뿐임:** 쇼츠만 다룹니다. 롱폼, 이미지, 블로그 글을 추가하려면 코드 수정이 필요합니다.
- **작업 현황이 보이지 않음:** 결과는 SQLite와 `report.json`에 남아서, 비개발자는 확인하기 어렵습니다.
- **실행 권한이 개발자에게만 있음:** 명령어를 아는 사람만 돌릴 수 있습니다.

### 시트로 바꾸면 얻는 것

| 항목 | 효과 |
|---|---|
| **입력의 자유** | 영상이 유튜브에 없어도 드라이브 파일로 시작할 수 있습니다. |
| **한 번만 입력** | 제목, 본문, 미디어를 한 번 적으면 형식별로 자동 변환됩니다. |
| **관리 편의** | 작업 목록, 승인, 상태를 시트에서 한눈에 봅니다. |
| **구성원 조회** | 조회 시트를 따로 공유해 상태만 보여 줄 수 있습니다. |
| **승인 절차** | "승인 = Y"인 행만 실행되므로 실수 게시를 막습니다. |
| **확장성** | 형식이 늘어도 시트 열은 그대로이고, 규칙 파일과 업로더만 추가합니다. |

## 3. 시트 구성

시트는 **작업 시트**(편집자 전용)와 **조회 시트**(구성원 보기 전용) 두 개로 나눕니다.
구글 시트는 사용자별로 열을 숨길 수 없기 때문입니다.

### 3.1 작업 시트

| 탭 | 행의 의미 | 주요 열 |
|---|---|---|
| **작업** | 게시 콘텐츠 1건 | 작업ID, 승인, 상태, 제목, 본문, 해시태그, 대상 형식(복수 선택), 결과 요약, 메모 |
| **블록** | 콘텐츠의 한 조각 (순서대로) | 작업ID, 순서, 종류(텍스트/이미지/영상), 내용, 파일ID |
| **오버라이드** | 형식별 예외 값 (드물게 사용) | 작업ID, 형식, 필드, 값 |

- **블록 탭**이 핵심입니다. 블로그의 "텍스트 → 이미지 → 텍스트" 순서나 캐러셀의 이미지 순서를 여기서 정합니다.
- **오버라이드 탭**은 특정 형식만 제목이나 공개 범위를 바꿔야 할 때만 씁니다.

### 3.2 조회 시트

한 행 = **작업 1건 × 플랫폼 1곳**

| 열 | 설명 |
|---|---|
| 작업ID | 작업 시트와 연결 |
| 제목 / 설명 | 작업 시트 값 복사 |
| 미디어유형 | 드롭다운 (영상 / 이미지 / 캐러셀 / 블로그) |
| 플랫폼 | 드롭다운 (유튜브, 인스타그램, 네이버 블로그 등) |
| 형식 | 드롭다운 (롱폼 / 쇼츠 / 게시물 / 블로그) |
| 상태 | 드롭다운 (대기 / 진행중 / 완료 / 일부실패 / 확인필요 / 의존실패) |
| 검증 | 드롭다운 (완료 / 없음) |
| 게시일시 | 날짜와 시간 |
| 결과URL | 게시물 링크 |
| 실패사유 | 사람이 읽을 수 있는 문장으로 기록 (구성원에게 공개) |
| 갱신시각 | 마지막 갱신 시각 |

## 4. 플랫폼 × 콘텐츠 형식 대치

### 4.1 형식 정의

| 형식 | 미디어 | 제목 | 본문 / 설명 | 블록 배치 |
|---|---|---|---|---|
| 유튜브-롱폼 | 가로 영상 1개 | 제목 사용 | 본문 + 해시태그 | 영상 블록 1개 |
| 유튜브-쇼츠 | 세로 영상 1개 | 제목 사용 | 본문 + 해시태그 | 영상 블록 1개 |
| 인스타-게시물 | 이미지 1~10장 | 사용 안 함 | 캡션 = 본문 + 해시태그 | 이미지 블록 (캐러셀) |
| 인스타-쇼츠 | 세로 영상 1개 | 사용 안 함 | 캡션 = 본문 + 해시태그 | 영상 블록 1개 |
| 네이버 블로그 | 텍스트와 이미지 | 제목 사용 | 블록을 순서대로 배치 | 텍스트, 이미지 삽입. 영상은 유튜브 링크로 대체 |

### 4.2 대치 규칙 요약

- **제목:** 기본 제목을 사용합니다. 오버라이드가 있으면 교체하고, 글자수를 넘으면 줄여서 기록합니다.
- **설명 / 캡션:** 본문과 해시태그를 정해진 순서로 합칩니다.
- **블록:** 형식이 요구하는 형태로 펼칩니다. 형식이 지원하지 않는 블록은 조용히 빼지 않고 확인필요로 멈춥니다.
- **미디어:** 형식별 비율, 길이, 용량, 장 수를 검사합니다.

### 4.3 의존 관계

- **블로그 → 유튜브:** 블로그 본문에 영상 링크를 넣으려면 유튜브 게시가 먼저 끝나야 합니다.
- 의존 대상이 실패하면 블로그는 실행하지 않고 **의존실패**로 기록합니다.
- 의존이 없는 형식은 계속 진행합니다.

## 5. 앞으로 확인해야 할 점

### 5.1 플랫폼 공식 정책과 규격 (구현 전 필수)

- [ ] 플랫폼별 영상 길이, 비율, 용량 제한 (인스타 릴스, 유튜브 쇼츠, 틱톡 등)
- [ ] 플랫폼별 제목과 캡션 글자수 제한 (네이버 블로그 제목 제한 포함)
- [ ] 이미지 게시 지원 여부와 권장 비율 (인스타 피드, 쓰레드, 링크드인 등)
- [ ] 캐러셀 장 수 제한과 지원 플랫폼
- [ ] 예약 게시 지원 여부

### 5.2 기술적으로 검증할 점

- [ ] 인스타그램 게시 방식: 현재 Playwright 유지 vs 공식 API 전환 (API 전환 시 영상 공개 URL 필요)
- [ ] 네이버 블로그에서 유튜브 링크가 자동으로 영상으로 바뀌는지 (에디터에서 실제 확인)
- [ ] 네이버 블로그에서 이미지 업로드 방식과 용량 제한
- [ ] 유튜브 업로드 방식: 공식 API 권장 vs Studio 자동화 (할당량과 미검증 프로젝트의 비공개 제한 확인)
- [ ] 구글 시트 API와 드라이브 API의 할당량

### 5.3 보안과 권한

- [ ] 서비스 계정 키 보관 위치 (`data/secrets/`, `.env`만 사용, 커밋 금지)
- [ ] 드라이브 파일은 서비스 계정에만 공유하고 링크 공개 금지
- [ ] 공개 URL이 필요한 경우 임시 서명 URL 저장소 검토 (예: S3)
- [ ] 조회 시트에 민감한 정보가 들어가지 않는지 주기적으로 확인

### 5.4 운영 정책

- [ ] 시트 관리자 지정 (1인 관리 / 공동 작업)
- [ ] 재게시 규칙 (어떤 조건에서 재게시를 허용할지)
- [ ] 자동 실행 주기와 실행 장비 (맥미니 launchd, 로컬 Windows 등)
- [ ] 로그인 세션 만료 시 처리 방법 (사람이 재로그인하는 절차)
- [ ] 자사 제품 홍보 콘텐츠의 광고 표기 필요 여부 (마케팅 또는 법무 확인)

### 5.5 구현 전 결정 사항

- [ ] 유튜브 업로드 방식 확정
- [ ] 인스타그램 게시 방식 확정
- [ ] 형식 추가 우선순위 (제안: 유튜브-쇼츠 → 인스타-쇼츠 → 인스타-게시물 → 유튜브-롱폼 → 네이버 블로그)

## 6. 구현 순서 (제안)

1. 소스 어댑터 구조 도입 및 기존 유튜브 동작 유지 테스트
2. 작업 탭 읽기 + 형식 규칙 (유튜브-쇼츠 한 가지)
3. 드라이브 다운로드 + 영상 한 건 게시
4. 상태 갱신과 중복 방지 기록
5. 게시 전 검증 단계 (확인필요 처리)
6. 블록 탭 (이미지, 캐러셀)
7. 형식 추가 (인스타, 롱폼, 블로그 순, 의존 관계 포함)
8. 소규모 실계정 테스트 후 주기 실행
