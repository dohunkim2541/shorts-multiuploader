# 설계: 시트 기반 멀티 게시 (형식별 규칙 + 영상/이미지)

상태: 초안 (구현 전, 조사 단계)
관련 문서: [longform-design.md](longform-design.md) (유튜브 롱폼 소스 설계. 입력 방식은 이 문서가 대체한다)

## 1. 목표

- 사람은 **콘텐츠 원본(제목, 본문, 미디어)**을 한 번만 입력한다.
- 게시 **형식**(유튜브 롱폼, 유튜브 쇼츠, 인스타 게시물, 인스타 쇼츠, 네이버 블로그)마다 필요한 값은 **형식 규칙이 계산**한다.
- 형식이 늘어나도 시트 구조는 바뀌지 않는다. 형식 추가는 규칙 파일과 업로더 추가로 처리한다.
- 기존 파이프라인의 게시, 검증, 상태 기록 구조는 재사용한다.

## 2. 핵심 원칙: 콘텐츠와 형식을 분리

| 구분 | 누가 정하나 | 어디에 두나 |
|---|---|---|
| **콘텐츠** (제목, 본문, 해시태그, 미디어 순서) | 사람 | 시트 (작업 탭, 블록 탭) |
| **형식 규칙** (어떤 콘텐츠를 어떻게 바꿔 쓸지, 미디어 제한) | 개발자 | 코드 저장소의 규칙 파일 |
| **예외 값** (특정 형식에서만 다른 값) | 사람, 드물게 | 시트 (오버라이드 탭) |

사람이 입력하는 열은 형식 수와 상관없이 **항상 같은 소수**입니다. 형식별 차이는 입력 대신 규칙으로 계산합니다.

## 3. 전체 흐름

```text
구글 시트 (작업 탭: 승인 = Y)
    -> 블록 탭 읽기 (순서대로: 텍스트 / 이미지 / 영상)
    -> 오버라이드 탭 읽기 (있을 때만)
    -> 대상 형식마다 형식 규칙 적용
         -> 제목, 캡션/설명, 블록 배치, 미디어 선택
    -> 검증 (형식 규칙 충족 여부)
         ├─ 실패: 게시하지 않음, 상태 = 확인필요, 사유 기록
         └─ 통과: 형식별 lane으로 전달
    -> Drive API로 파일 다운로드 -> 변환 (ffmpeg, Pillow)
    -> 플랫폼 업로더 (upload / verify)
    -> 작업 탭 결과 열 + 조회 시트 갱신
```

재사용하는 부분: 업로더 계약(`upload`, `verify`), 글자수 축약, 정책 규칙, 실패 시 복구 흐름, run report.

## 4. 시트 구성: 탭 3개 + 조회 탭

시트 한 장에 모든 열을 넣지 않고 역할별로 나눕니다.

### 4.1 작업 탭 (행 1개 = 게시 콘텐츠 1건)

| 열 | 형식 | 필수 | 설명 |
|---|---|---|---|
| 작업ID | 텍스트 | 예 | 행을 식별하는 키 (예: JOB-0007) |
| 승인 | Y / 빈칸 | 예 | Y인 행만 실행. 실수 게시 방지 |
| 상태 | 드롭다운 | 자동 | 대기 / 진행중 / 완료 / 일부실패 / 확인필요 |
| 제목 | 텍스트 | 예 | 원본 제목. 형식별로 줄이거나 바꿈 |
| 본문 | 텍스트 (긴 글) | 아니오 | 원본 본문. 블록이 있으면 본문은 요약용으로만 사용 |
| 해시태그 | 텍스트 | 아니오 | 캡션과 설명 끝에 붙임 |
| 대상 형식 | 드롭다운 (복수 선택) | 예 | 유튜브-롱폼, 유튜브-쇼츠, 인스타-게시물, 인스타-쇼츠, 네이버블로그 |
| 결과 요약 | 텍스트 | 자동 | 형식별 결과를 요약 (상세는 조회 탭) |
| 메모 | 텍스트 | 아니오 | 작업자 메모. 파이프라인은 읽지 않음 |

### 4.2 블록 탭 (행 1개 = 콘텐츠의 한 조각, 순서대로)

| 열 | 형식 | 설명 |
|---|---|---|
| 작업ID | 텍스트 | 작업 탭과 연결 |
| 순서 | 숫자 | 1, 2, 3 ... 순서대로 배치 |
| 종류 | 드롭다운 | 텍스트 / 이미지 / 영상 |
| 내용 | 텍스트 | 종류가 텍스트면 본문 조각 |
| 파일ID | 텍스트 | 종류가 이미지 또는 영상이면 드라이브 파일 ID |

- **상하 스크롤 블로그**는 이 탭이 핵심입니다. 텍스트와 이미지가 섞인 순서를 그대로 기록합니다.
- **인스타 게시물(캐러셀)**은 "이미지" 블록을 순서대로 모아서 만듭니다.
- **유튜브 영상**은 "영상" 블록 1개면 충분합니다.
- 기존 "파일ID 1~10" 열은 이 탭으로 대체합니다.

### 4.3 오버라이드 탭 (예외만 입력)

| 열 | 설명 | 예시 |
|---|---|---|
| 작업ID | 대상 작업 | JOB-0007 |
| 형식 | 적용할 형식 | 네이버블로그 |
| 필드 | 바꿀 항목 | 제목 |
| 값 | 바꿀 내용 | 블로그용 제목 |

- 오버라이드가 없으면 이 탭은 비어 있어도 됩니다.
- 허용 필드는 형식 규칙 파일에 정의된 항목으로 제한합니다. 목록에 없는 필드는 검증에서 거부합니다.
- 공개 범위, 공개 설정처럼 형식마다 기본값이 있는 항목을 바꿀 때 주로 씁니다.

### 4.4 조회 시트 (보기 전용, 별도 파일)

한 행 = 게시 작업 1건 × 플랫폼(형식) 1곳입니다. 한 콘텐츠를 3개 형식에 올리면 3행이 생깁니다.

| 열 | 형식 | 예시 | 채워지는 방식 |
|---|---|---|---|
| 작업ID | 텍스트 | JOB-0007 | 파이프라인 |
| 제목 | 텍스트 | 신제품 출시 | 파이프라인 (작업 탭 값 복사) |
| 설명 | 텍스트 (긴 글) | 본문 | 파이프라인 (형식 규칙으로 만든 설명) |
| 미디어유형 | 드롭다운 | 영상 / 이미지 / 캐러셀 / 블로그 | 파이프라인 |
| 플랫폼 | 드롭다운 | 유튜브 / 네이버 블로그 / 인스타그램 / 쓰레드 / 틱톡 / 링크드인 / 페이스북 / 네이버 클립 | 파이프라인 |
| 형식 | 드롭다운 | 롱폼 / 쇼츠 / 게시물 / 블로그 | 파이프라인 |
| 상태 | 드롭다운 | 대기 / 진행중 / 완료 / 일부실패 / 확인필요 | 파이프라인 |
| 검증 | 드롭다운 | 완료 / 없음 | 파이프라인 |
| 게시일시 | 날짜시간 | 2026-10-10 10:00 | 파이프라인 |
| 결과URL | 텍스트 (링크) | 플랫폼 게시물 주소 | 파이프라인 |
| 실패사유 | 텍스트 | 캡차 발생, 재시도 필요 | 파이프라인 (구성원에게 공개) |
| 갱신시각 | 날짜시간 | 2026-10-10 10:05 | 파이프라인 |

**구현 메모**
- 플랫폼, 형식, 상태, 검증, 미디어유형은 **데이터 확인(드롭다운)**으로 값을 제한합니다. 오타로 필터가 깨지는 것을 막습니다.
- 플랫폼 목록은 `platforms.py`의 이름과 같은 값을 씁니다.
- **실패사유**는 사람이 이해할 수 있는 문장으로만 씁니다. 로그 원문, 계정 정보, 파일 경로는 넣지 않습니다.

### 4.5 작업 시트와 조회 시트 분리

- 작업 시트(작업, 블록, 오버라이드 탭)는 편집자(본인, 서비스 계정)만 접근합니다.
- 조회 시트는 회사 구성원에게 **보기 전용**으로 공유합니다.
- 구글 시트는 사용자별 열 숨김을 지원하지 않으므로 두 파일로 나눕니다.
- 쓰기 흐름: 파이프라인은 처리 결과를 **작업 탭 결과 요약에 먼저 기록**한 뒤, 같은 값을 조회 시트에 씁니다.
- 드라이브 파일 권한은 별도입니다. 조회 시트를 본다고 원본 영상을 볼 수 있는 것은 아닙니다.

## 5. 형식 규칙

형식마다 "무엇을 어떻게 바꿔 쓰는지"를 규칙 파일에 적습니다. 예시 (값은 전부 **구현 전 확인 필요**):

| 형식 | 제목 | 본문/설명 | 블록 배치 | 미디어 제약 |
|---|---|---|---|---|
| 유튜브-롱폼 | 제목 (글자수 확인) | 본문 + 해시태그 | 영상 블록 1개 | 가로 영상, 기본 공개 범위는 비공개 |
| 유튜브-쇼츠 | 제목 (글자수 확인) | 본문 + 해시태그 | 영상 블록 1개 | 세로 영상, 길이 검사 |
| 인스타-게시물 | 사용 안 함 | 캡션 = 본문 + 해시태그 (2,200자 이내) | 이미지 블록 (캐러셀) | 비율과 장수 검사 |
| 인스타-쇼츠 | 사용 안 함 | 캡션 = 본문 + 해시태그 | 영상 블록 1개 | 세로 영상, 자르기는 `원본` 선택 |
| 네이버블로그 | 제목 (24자 제한 여부 확인) | 블록을 순서대로 배치 | 텍스트와 이미지 삽입, 영상은 유튜브 링크로 대체 | 블록 순서, 본문 길이 |

**규칙의 공통 구조**
- 제목 규칙: 기본 제목 사용, 오버라이드가 있으면 교체, 글자수를 넘으면 줄이고 기록
- 설명 규칙: 본문 + 해시태그를 정해진 순서로 합침
- 블록 규칙: 블록을 순서대로 펼쳐서 형식이 요구하는 형태로 변환
- 미디어 규칙: 형식별 비율, 길이, 용량, 장수 제한

**형식 추가 방법:** 규칙 항목 하나와 업로더 모듈 하나를 추가합니다. 시트 열은 바꾸지 않습니다.

## 6. 블록 배치 예시

작업 탭 한 행: `JOB-0007 | 승인 Y | 제목 "신제품 출시" | 해시태그 "#신제품" | 대상 형식 "유튜브-쇼츠, 인스타-쇼츠, 네이버블로그"`

블록 탭:

| 작업ID | 순서 | 종류 | 내용 | 파일ID |
|---|---|---|---|---|
| JOB-0007 | 1 | 영상 | | 1AbC... (세로 영상) |
| JOB-0007 | 2 | 텍스트 | 신제품 소개 문단 | |
| JOB-0007 | 3 | 이미지 | | 1XyZ... |
| JOB-0007 | 4 | 텍스트 | 구매 안내 문단 | |

결과 (형식 규칙 적용):
- **유튜브-쇼츠:** 영상 1번 블록 사용, 제목과 설명 입력
- **인스타-쇼츠:** 같은 영상, 캡션 = 본문 + 해시태그
- **네이버블로그:** 텍스트 → 이미지 → 텍스트 순서로 배치. 블록에 영상이 있으면 **유튜브 게시 결과 URL을 링크로 삽입**

## 7. 의존 관계와 순서

- **블로그는 유튜브 결과에 의존할 수 있습니다.** 블로그 본문에 영상 링크를 넣으려면 유튜브 게시가 먼저 끝나야 합니다.
- 규칙: 같은 작업에서 의존 대상 형식이 실패하면 **의존하는 형식은 실행하지 않고 "대기(의존 실패)"로 기록**합니다.
- 의존이 없는 형식은 계속 진행합니다 (lane 격리 유지).

## 8. 검증 단계 (게시 전)

게시하기 전에 형식 규칙을 모두 확인합니다. 하나라도 어긋나면 게시하지 않고 **상태 = 확인필요, 실패사유 기록**으로 멈춥니다.

확인 항목:
- 필수 필드 존재 (예: 블로그 제목)
- 허용 필드만 오버라이드됨
- 미디어 파일 존재, 형식, 비율, 길이, 용량
- 글자수 제한 (줄인 결과는 기록)
- 블록 순서가 비어 있거나 중복되지 않음
- 의존 형식 결과가 준비됨

## 9. 미디어 위치와 보안

- 구글 드라이브 **파일 ID**를 사용합니다. 공유 링크를 그대로 쓰지 않습니다.
- 서비스 계정에만 파일을 공유하고, **링크 공개는 하지 않습니다.**
- 인스타 API 방식처럼 공개 URL이 필요하면, 드라이브 파일을 공개하지 말고 **임시 서명 URL**을 만들 수 있는 저장소(예: AWS S3)를 검토합니다.
- 인증 정보(서비스 계정 키, 토큰)는 `.env`와 `data/` 아래에만 두고 커밋하지 않습니다.

## 10. 미디어 종류별 처리

- **영상:** H.264 MP4. 기존 `ffmpeg` 변환 단계를 씁니다. 인스타는 H.264 MP4만 받습니다 (`instagram.py` 주석).
- **이미지:** JPG, PNG. 필요하면 `Pillow`로 변환합니다. 플랫폼 권장 비율을 검사하고, 자동 자르기로 의도와 다른 화면이 나오지 않도록 경고를 남깁니다.
- **캐러셀과 블로그 이미지:** 블록 순서를 그대로 따릅니다. 형식이 지원하지 않는 블록이 있으면 **조용히 빼지 않고** 확인필요로 멈춥니다.

## 11. 플랫폼 지원 매트릭스 (조사 필요)

아래는 제 학습 데이터 기준의 추정입니다. 구현 전에 플랫폼 공식 문서로 확인해야 합니다.

| 플랫폼 | 영상 | 이미지 | 캐러셀 | 비고 |
|---|---|---|---|---|
| 유튜브 | 지원 | 커뮤니티 게시물 별도 | 해당 없음 | 이미지 전용 일반 게시 방식 확인 필요 |
| 네이버 블로그 | 유튜브 링크로 대체 | 본문에 삽입 | 본문에 여러 장 | 이미지 업로드 방식과 용량 확인 필요 |
| 인스타그램 | 릴스 | 피드 | 지원 | API 방식이면 공개 URL 필요 |
| 쓰레드 | 지원 | 지원 | 지원 | 확인 필요 |
| 틱톡 | 지원 | 사진 게시 | 지원 | 확인 필요 |
| 링크드인 | 지원 | 지원 | 문서형 | 확인 필요 |
| 페이스북 | 릴스 / 동영상 | 지원 | 지원 | 페이지 계정 여부에 따라 다름 |
| 네이버 클립 | 지원 | 확인 필요 | 확인 필요 | 기존 업로더는 영상 중심 |

## 12. 상태와 중복 방지

- 상태 값: `대기` → `진행중` → `완료` / `일부실패` / `확인필요` / `의존실패`
- 키는 `(작업ID, 형식)`입니다. 한 번 게시한 기록은 다시 올리지 않습니다.
- **검증 전에는 재업로드하지 않습니다.** 기존 규칙과 같습니다.
- 한 형식이 실패해도 의존 관계가 없는 다른 형식은 계속 진행합니다.
- 재게시가 필요하면 작업 탭에 "재게시 = Y"를 명시적으로 표시하는 방식을 검토합니다. (미정 사항 5 참고)

## 13. 소스 구조 변경

현재 `youtube.py`에 묶인 입력 부분을 **소스 어댑터**로 나눕니다.

```text
src/shorts_distributor/sources/
    base.py        # 공통 인터페이스: 작업 목록 조회, 블록 조회
    youtube.py     # 기존 유튜브 수집 (롱폼/숏폼 탭)
    sheet.py       # 신규: 작업/블록/오버라이드 탭 -> 게시 작업
    drive.py       # 신규: 드라이브 파일 다운로드
src/shorts_distributor/formats/
    rules.yaml     # 신규: 형식별 규칙 (제목, 설명, 블록 배치, 미디어 제약)
    validate.py    # 신규: 게시 전 검증
```

- 중복 방지 키를 `youtube_id`에서 `(소스, 작업ID, 형식)`으로 바꿉니다.
- 기존 `state.py` 스키마에 소스, 작업ID, 형식 열을 추가해야 합니다.

## 15. 테스트 계획

- 탭 파싱: 필수 열 누락, 승인 값 대소문자, 블록 순서 중복과 빈칸
- 형식 규칙: 형식별 제목, 설명, 블록 배치 결과가 규칙과 일치하는지
- 오버라이드: 허용되지 않은 필드 거부
- 검증 단계: 미디어 비율, 길이, 글자수, 필수 필드 실패 시 게시하지 않음
- 의존 관계: 유튜브 실패 시 블로그가 실행되지 않고 "의존실패"로 기록되는지
- 상태 전이: 완료된 형식 재실행 시 중복 게시가 없는지
- lane 격리: 한 형식 실패 시 의존 없는 다른 형식이 계속 진행하는지
- 실계정 테스트는 테스트 계정과 테스트 시트에서만 수행하고, CI에서는 실제 게시를 하지 않음

## 16. 미정 사항

1. 시트를 누가 관리하는지 (본인 단독 / 여러 사람 공동 작업)
2. 형식별 제목 글자수, 본문 길이, 이미지 비율과 용량 규칙 확정
3. 인스타 게시 방식 (Playwright 유지 / API 전환 후 공개 URL 저장소 필요)
4. 예약 게시 지원 여부와 지원 플랫폼
5. 재게시 규칙 (어떤 조건에서 재게시를 허용할지)
6. 유튜브 게시 방식 (API 권장 / Studio 대안, `longform-design.md` 참고)
7. 블로그에 영상을 링크로 대체하는 방식이 실제 에디터에서 동작하는지

## 17. 구현 순서 제안

1. 소스 어댑터 구조 도입 + 기존 유튜브 동작 유지 테스트
2. 작업 탭 읽기 + 형식 규칙 파일 (유튜브-쇼츠 한 가지만)
3. 드라이브 다운로드 + 영상 한 건 게시
4. 상태 열 갱신과 중복 방지 기록
5. 검증 단계 추가 (확인필요 처리)
6. 블록 탭 (이미지, 캐러셀)
7. 형식 추가: 인스타-쇼츠 → 인스타-게시물 → 유튜브-롱폼 → 네이버블로그 (의존 관계 포함)
8. 소규모 실계정 테스트 후 주기 실행 설정
